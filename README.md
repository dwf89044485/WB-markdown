# WorkBuddy 动态原型实现说明

这个版本把原来的单文件静态最终态拆成三层：

- `index.html`：只保留手机壳、导航、输入框、对话容器、底部浮层等视觉骨架。
- `styles.css`：从 `x.html` 原样抽取视觉 CSS，仅追加运行态辅助类，例如扫光和事件卡片。
- `scenario.js`：按 `02-节点剧本(2).md` 把节点、子事件、状态行、浮层快照、待办状态做成数据。
- `app.js`：播放引擎，负责节点出现、状态行推进、浮层帧切换、节点自动塌缩、收尾 timing-bar 和正文输出。

关键设计约束：

1. 不改视觉体系：继续使用 `x.html` 里的 class、圆角、字号、间距和组件结构。
2. 不把剧本写死进 HTML：后续改剧本时主要改 `scenario.js`。
3. 浮层不是累积日志：每条状态行绑定自己的最后一帧，点击时展示对应快照。
4. timing-bar 只在全部节点结束后出现。
5. 旧实现里的节点3删除项没有迁入：不再出现“原生中文字符重写整个文件”和“已调用工具”。

直接打开 `index.html` 即可播放。若浏览器因本地脚本策略拦截，可在该目录运行：

```bash
python3 -m http.server 8000
```

然后访问本地服务页面。


## 本轮调整

- 演示从用户消息发送开始：先出现用户气泡，再出现 WorkBuddy，再显示「思考过程」loading，最后进入节点 1。
- 子状态触发行只保留文字里的 `›`，移除额外 SVG 箭头，避免出现一粗一细两个箭头。
- 连续状态会自动合并成同一个触发行，例如节点 2 会从「正在生成图片 ›」推进到「生成图片、正在更新待办 ›」，最终停在「生成图片、更新待办 ›」。点击这一整句话时，浮层会把生成图片事件放在上方，把更新待办和待办快照放在下方。

## v4 Markdown 文案与样式更新

- 节点 1 的 Markdown 文案已替换为最新版本，表格恢复「子任务 / 目的 / 输入 / 输出」四列。
- 最终汇报内容保持与最新文案一致，成果链接使用移动端卡片化样式。
- Markdown 视觉已抽象为 CSS token，详见 `MARKDOWN_STYLE_TOKENS.md`。
- 节点内 Markdown 和最终汇报 Markdown 共用 `.md` 样式体系；节点内仅通过 `.md-node` 进行字号收敛和左缩进。

## v5 交互与播放参数更新

- 运行中的状态行文字改为 `#00AF92`，扫光效果保留。
- 打字速度从旧版 `ms/字符` 改为 `tokens/s`，默认 `200 tokens/s`，数字输入框步进为 `20`。
- 「刷新重放」改为播放器内部重置：清空当前 DOM、取消旧播放任务并立即启动新一轮，不再通过 URL 参数触发整页重新加载。

## v6 更新

- 运行中的状态行恢复为原始灰色视觉，保留扫光动画。
- 新增演示步进器：上一步 / 自动播放（停止）/ 下一步。
- 步进器按导演时间轴推进，粒度覆盖用户消息、Agent 进场、思考过程、节点出现、节点内状态行/Markdown、最终汇报。
- 上一步采用快速重建方式回到上一演示节点，避免依赖不可逆的 DOM 动画状态。


## v7 更新

- Markdown 表格改为移动端自适应，不再产生独立横向滚动条。
- 浮层视觉按参考截图精调：更大的圆角、居中标题、右上圆形关闭按钮、时间线式事件列表。
- 将上传的 SVG 工具图标纳入 `icons/`，并在浮层中按工具类型自动匹配：思考/图片/技能/编辑/查看/搜索网页/搜索文件/终端/待办/异常。
