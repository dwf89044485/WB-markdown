# 规范定稿定界

## 用户

好，现在你要作为架构师来推进完成工作，你带着我往下推进，系统性思考每一轮对话都应该干什么，在每一轮对话末尾应该引导我下一步怎么做。
注意，我是产品体验设计师，我不管底层字段处理研发逻辑，我核心目标有3个，第一，把交互逻辑流程、渲染流程、信息分级、原则指南等等等等这些形成文档沉淀下来，第二，有一个demo可以让团队的人体验感受，第三，有一个评审页，评审页可以步进，让大家可以一个节点一个节点来控制播放，每一个节点可能都会写一些交互逻辑。我的demo，纯演示，数据纯mock，不接后端不接llm。
所以你在帮我梳理沉淀文档的时候，围绕我的目标来，内容的深度、颗粒度都控制好，不要超过我的目标，不要搞得太复杂太冗长精准凝练即可。系统性思考清楚再来

## 助手

明白。接下来我会用“架构师 / 体验负责人”的方式带你推进：不把事情搞成研发系统设计，不陷入底层字段、后端状态机、LLM 协议，而是围绕你作为产品体验设计师真正要交付的三件东西推进。
你的目标我先收束成这三个交付物：

1. 一套文档沉淀
交互逻辑、流程、渲染流程、信息分级、原则指南、反模式、示例说明
2. 一个可体验 Demo
纯 mock、纯演示、不接后端、不接 LLM，让团队直观看懂完成态、展开态、下钻态
3. 一个评审页
可步进播放，每一步展示一个节点 / 状态 / 交互逻辑，方便团队逐节点评审
我会把所有工作都围绕这三件事组织。
1. 我们现在不是做“规范全集”，而是做“体验表达系统”
这里要先控范围。
我们不做：

不做后端字段设计
不做真实 Run 数据结构
不做 LLM 执行协议
不做工具调用 schema
不做复杂工程状态机
不做生产级组件库
我们要做的是：

让团队理解：Agent 对话流应该怎么展开、怎么折叠、怎么下钻、怎么验收
让设计师能复用：以后遇到 Agent 执行过程，都知道怎么分层表达
让评审可推进：不是口头讲，而是一步步播放给大家看
所以文档深度应该是：
**足够指导体验设计和评审，不深入到研发实现细节。**
2. 我建议把整个项目拆成三条主线
主线 A：文档规范线
目标是沉淀成一套设计文档。
核心内容：

Agent Run 是什么
执行过程态 / 结果交付态是什么
完成后为什么折叠过程
信息如何分级
主对话、展开区、浮层分别承载什么
不同层级应该显示什么、不显示什么
错误、工具、原始日志怎么处理
设计原则和反模式是什么
这条线最终产出一份主文档：
**《Agent Run 对话流体验规范 v0.1》**
它是团队以后讨论这类体验的共同语言。
主线 B：Demo 体验线
目标是做一个团队能点、能感受的 Demo。
它不需要真实执行，只需要 mock 一个典型任务，比如你截图里的：
生成日本关西家庭旅行方案
Demo 需要让团队体验到：

完成态：默认只看结果
展开态：点击执行过程
节点态：展开某个节点
复杂节点态：看到工具 / 文件 / 命令事件
浮层态：查看工具详情
深层浮层态：查看命令和输出
Demo 是“感受用”的，不是评审逐步讲解用的。
主线 C：评审页线
目标是做一个可以控制节奏的讲解页。
它和 Demo 不一样。
Demo 是让人自由点。
评审页是你主导讲解：

Step 1：用户看到完成态
Step 2：点击执行过程
Step 3：展开节点列表
Step 4：打开任务理解节点
Step 5：打开复杂文档生成节点
Step 6：进入工具浮层
Step 7：进入命令详情
Step 8：回到结果验收
每一步旁边写：

这一屏解决什么问题
用户为什么需要它
默认展示什么
哪些信息被折叠
为什么用主流 / 展开 / 浮层承载
评审页是“讲清楚逻辑用”的。
3. 我建议的推进顺序
不要三条线同时开。应该先文档框架，再 Demo，再评审页。
原因是：Demo 和评审页都要依赖同一套体验框架。如果先做 Demo，容易做成局部交互；如果先做评审页，容易变成讲稿。先把框架定住，后面会稳。
我建议这样推进：

第 1 轮：确定总框架
第 2 轮：写主文档 v0.1
第 3 轮：拆 Demo 脚本
第 4 轮：定义 Demo 页面结构
第 5 轮：定义评审页步进脚本
第 6 轮：生成 Demo HTML
第 7 轮：生成评审页 HTML
第 8 轮：回收修改，形成最终包

6. 现在我建议第一步做什么

我建议主框架如下：

# Agent Run 对话流体验规范 v0.1
## 1. 这套规范解决什么问题
Agent 对话流不是聊天回复，而是任务执行后的结果交付与过程追溯。
## 2. 核心对象：Agent Run
一次用户委托触发一次 Run。Run 包含结果、过程、节点、事件、工具、原始记录。
## 3. 两个阶段
执行过程态：让用户感知推进、必要时接管。
结果交付态：让用户验收结果，过程默认折叠。
## 4. 六级信息层级
L0 结果呈现层
L1 执行过程总览层
L2 节点摘要层
L3 节点内事件层
L4 工具 / 技能详情层
L5 原始命令 / 原始输出层
## 5. 三种承载介质
主对话流
对话内展开
浮层下钻
## 6. 典型交互链路
完成态 → 展开执行过程 → 展开节点 → 查看复杂事件 → 打开工具浮层 → 打开命令详情
## 7. 展示原则
结果优先
过程可查
完成后折叠
任务语言优先
细节逐级下钻
高密度日志进入浮层
## 8. 关键反模式
过程污染结果
完全黑盒
工具名主导叙事
原始日志堆进主流
完成态太弱
## 9. Demo 与评审页如何承接
Demo 用来体验。
评审页用来逐步讲解。
这份文档不需要特别长，但要足够稳定，后面 Demo 和评审页都从这里长出来。
