# WorkBuddy · Apple Design 体验优化交接清单

> **用途**：把 Apple Design 审查转为可独立执行的实施队列。每个新会话只领取一项任务；完成、验证、提交后，更新本文件，再将本文件交给下一会话。
>
> **范围边界**：本清单同时覆盖左侧手机 Demo（Agent 产品体验）、右侧 Feature Panel（设计说明的阅读体验）和下方 Demo 控制台（作者操作体验）。不把 Apple Design 狭义化为动画：重点是承诺可信、操作可控、空间关系清楚、不同能力和设备下仍可用。

## 0. 交接协议（每个新会话先读）

### 领取方式

1. 先阅读本文件、`AGENTS.md` 和任务涉及的现有实现；不要依据本清单直接假设代码仍未变化。
2. 只领取状态为 `待执行`、且依赖已完成的**一项**任务。
3. 若实现中发现范围必须扩大：在本文件的「变更记录」中写明原因、影响和新增依赖；不跨入其他任务的主范围。
4. 产品体验、不可逆操作或需要素材时才向用户提问；纯技术实现自行决策。

### 完成方式

每项完成后必须：

1. 在浏览器手动验证该任务的验收项；开发入口为 `python3 -m http.server 8080`，不要用 `file://` 直接打开。
2. 运行与改动相称的静态检查或测试；至少运行 `git diff --check`。
3. 仅暂存本任务直接相关的文件并提交。**工作区有其他未跟踪内容，禁止使用 `git add -A`。**
4. 在本文件中更新：任务状态、完成摘要、验证结果、commit hash、遗留问题与下一项任务的注意点。
5. 默认不推送，由用户决定是否推送。

### 当前工作区保护

截至本清单创建时，下列未跟踪内容不属于 Apple Design 优化任务，后续会话不得顺手修改、删除或提交：

- `HANDOFF-agents-md-refactor.md`
- `design-shotgun/`
- `design-shotgun.zip`

### 固定设计约束

- Sheet 的数据、渲染、样式、交互只能分别落在 `scenario.js`、`engine/sheet.js`、`styles/sheet.css` 的既有边界内。
- 右侧 Feature Panel 内容只能通过 `features/<id>.js` 注册；快照必须复用 Demo 现有 `renderStaticXxx()`，禁止重写组件 HTML。
- 间距与视觉规格沿用现有 token / class；不要为单个任务引入新的无体系硬编码。
- Apple 式弹簧、惯性和阻尼只用于用户直接操控的对象（尤其 Sheet）；**不要**把播放引擎、打字机或所有状态行改成物理动画。
- 不要为普通查看型 Sheet 或问答关闭动作普遍增加二次确认；只有关闭会造成不可恢复输入丢失时才考虑确认。

### 02 · 建立可缩放、低动态的适配底座

- **状态**：待执行
- **依赖**：01 完成。
- **目标**：在放大阅读、减少动态、降低透明度和高对比偏好下，信息仍清楚、控件仍可用。
- **用户问题**：页面禁止浏览器缩放；无限旋转、扫光、滑切、Sheet 位移等没有降级出口。
- **主要文件**：
  - `index.html`
  - `styles/base.css`
  - `styles/composer.css`
  - `styles/conversation.css`
  - `styles/sheet.css`
  - `styles/ask-question.css`
  - `styles/markdown.css`
  - `styles/feature-panel.css`
- **建议实现**：
  1. 移除 viewport 的 `maximum-scale=1.0` 与 `user-scalable=no`。
  2. 建立共享的 `prefers-reduced-motion: reduce`：保留必要的颜色/文字状态，停用循环动画与大范围位移，将关键进入/退出改为短淡入淡出或即时状态。
  3. 建立 `prefers-reduced-transparency: reduce` 与 `prefers-contrast: more`：提高浮层、导航、毛玻璃层背景不透明度和边界对比。
  4. 不要一次性重写全站 px 字号；只修复缩放时明显会遮挡、溢出或无法阅读的核心区域，并记录后续排版债务。
- **验收**：
  - 浏览器可缩放；放大后对话、输入框、Sheet、表格全屏可阅读且不遮挡主要操作。
  - 减少动态时无持续 spinner、扫光、光标闪烁或大幅滑动；状态含义仍可辨。
  - 减少透明度 / 高对比时，浮层和文字对比度明显提升。
- **非目标**：本任务不改变每个组件的业务流程，也不调整 Sheet 的手势物理逻辑。
- **完成记录**：待填写。

### 03 · 恢复键盘路径与焦点反馈

- **状态**：待执行
- **依赖**：02 完成。
- **目标**：每一个真实可操作控件都可通过键盘抵达，并有不破坏视觉体系的聚焦提示。
- **用户问题**：输入框、问答、全屏返回等许多真实操作带有 `tabindex="-1"`；若干样式移除了 outline 却没有替代焦点态。
- **主要文件**：
  - `index.html`
  - `engine/ask-question.js`
  - `styles/base.css`
  - `styles/composer.css`
  - `styles/ask-question.css`
  - `styles/markdown.css`
  - `styles/demo-controls.css`
- **建议实现**：
  1. 清点 `tabindex="-1"`，仅保留给纯装饰或已有等价原生语义的元素；真实按钮恢复默认 Tab 顺序。
  2. 用统一 `:focus-visible` 样式替代“去掉 outline”的做法；应有足够对比且不会破坏手机 Demo 的视觉密度。
  3. 验证 Tab 顺序遵循用户从顶部内容到当前操作区的阅读顺序，不产生焦点陷阱。
- **验收**：
  - 键盘可以抵达菜单、输入框工具、发送/停止、问答、Sheet 操作、表格全屏返回及工具栏。
  - 鼠标点击不出现多余焦点环，键盘聚焦清晰可见。
  - 无正序 Tab 无法离开的控件或循环。
- **非目标**：本任务不建立模态焦点约束（交由 04），不改变问答的具体选择逻辑（交由 05）。

### 04 · 补齐浮层的进入与退出闭环

- **状态**：待执行
- **依赖**：03 完成。
- **目标**：Sheet、表格全屏、输入框全屏、问答与权限卡片都具备清楚的“从哪里进入、当前在哪里、如何退出、回到哪里”。
- **用户问题**：这些界面视觉上是模态任务，但没有稳定的 dialog 语义、焦点进入/归还、Escape 退出和背景隔离。
- **主要文件**：
  - `index.html`
  - `engine/sheet.js`
  - `engine/table-fullscreen.js`
  - `engine/ask-question.js`
  - `engine/approve-permission.js`

- **建议实现**：
  1. 先抽取或在既有代码中实现最小的模态生命周期，不为一次性需求另造复杂框架。
  2. 打开时记录触发元素，将焦点放到任务标题、第一项输入或返回/关闭按钮；关闭时归还焦点。
  3. 支持 Escape；模态开启时隔离背景的键盘焦点与读屏访问。
  4. 仅对真正阻断当前任务的层使用 `role="dialog"` / `aria-modal="true"`；非阻断面板不要误标模态。
- **验收**：

- **非目标**：不增加不必要的“确认关闭”弹窗；不改变 Sheet 拖拽手感（交由 06）。

### 06 · 将 Sheet 变为连续直接操控

- **状态**：待执行
- **依赖**：04 完成。
- **目标**：Sheet 在拖动时持续跟手，松手后按位置与速度自然落到半屏、展开或关闭；任意时刻可重新抓住并反向操作。
- **用户问题**：当前使用 mouse/touch 分支和 document 监听；高度上限与最终展开高度不一致，存在跳变；向下超阈值立即关闭，没有阻尼和速度判断。
- **主要文件**：
  - `engine/sheet.js`
  - `styles/sheet.css`
- **建议实现**：
  1. 用 Pointer Events + `setPointerCapture` 统一输入路径，并保留纵向手势意图阈值，避免与内部滚动冲突。
  2. 记录最近数帧位置与时间，释放时将速度与当前高度共同用于目标档位判断。
  3. 拖动全程从当前展示值继续；超出上/下边界使用渐进阻尼，不要硬停或立刻关闭。
  4. 仅为此直接操控使用可中断的 spring / 速度交接；若没有既有依赖，采用最小可维护实现，先查现成方案再决定是否新增依赖。
  5. 保留内容在顶部才允许从展开态下拉收起的规则，避免抢夺正常滚动。
- **验收**：
  - 手指/鼠标离开面板边界仍能完成拖拽。
  - 从半屏上拉、展开下拉、拖到边界和快速甩动都连续，没有 80% → 90% 跳变。
  - 动画过程中可重新拖拽并立即反向。
  - 普通点击、内部滚动、遮罩关闭不回归。
- **非目标**：不把 Sheet 改成多档位系统，不更改 `scenario.js` 的浮层数据结构。
- **完成记录**：待填写。

### 08 · 为流式过程建立克制的状态播报

- **状态**：待执行
- **依赖**：02、04 完成。
- **目标**：让辅助技术用户知道 Agent、工具步骤和 Sheet 是否推进，同时不把逐字输出变成噪音。
- **用户问题**：打字机和 Sheet 会持续更新 DOM，但没有语义化的阶段性进度反馈。
- **主要文件**：
  - `index.html`
  - `engine/typewriter.js`
  - `engine/player.js`
  - `engine/sheet.js`
  - 必要时 `engine/ask-question.js` / `engine/approve-permission.js`
- **建议实现**：
  1. 提供一个独立、简短的 `aria-live="polite"` 状态区。

  3. 绝不按 token、字符或每条日志播报。
- **验收**：
  - 正常播放期间存在阶段性、可理解的进度信息。
  - 不会产生逐字重复或持续刷屏的读屏输出。
  - 快进、暂停、重播和跳转不会遗留过期播报。
- **非目标**：不加入声音、震动或每一步视觉动画。

### 09 · 让右侧说明栏成为清楚的体验地图

- **状态**：待执行

- **目标**：读者首次进入就知道此处说明什么、能验证什么；功能导航与左侧锚点跳转始终有反馈。
- **用户问题**：默认总览仍有“待补充”信号；功能标签持续增长后会形成平级按钮墙；锚点跳转失败或超时会静默停止。
- **主要文件**：
  - `features/overview.js`
  - `features/index.js`
  - `engine/feature-panel.js`
  - `engine/feature-jump.js`
  - `styles/feature-panel.css`
  - 需要时 `docs/交互设计说明/{DESIGN,EXPERIENCE,DECISIONS}.md`
- **建议实现**：
  1. 将总览补为一页真实入口：目的、如何阅读左右联动、核心原则、功能导航；或在它完成前把默认入口改为已成熟页面。优先前者。
  2. 以“产品原则 / 对话交互 / 内容容器 / 导航与适配”等读者心智组织功能入口，避免单纯累加标签。
  3. 锚点跳转提供进行中、成功和失败/超时的可恢复状态，避免吞掉错误。
  4. 遵守 Feature Panel 内容和静态快照规范，不在 engine 内散写说明正文。
- **验收**：
  - 首屏不再以未完成占位为主信号。
  - 读者能看懂当前在哪个说明主题、下一步能看什么。
