# Pad 模式设计计划

## 背景

当前 Demo 只支持手机尺寸（393×852），需要增加 Pad 尺寸切换能力，让用户可以在手机和 Pad 两种视图间切换，查看设计在不同屏幕尺寸下的表现。

## 核心决策

### 网格切分方案

| 项目 | 手机（现有） | Pad（推荐） |
|------|------------|------------|
| 壳尺寸 | 393×852 | **700×1050** |
| 等分 | 6×12 | **10×15** |
| 格子 | 65.5×71（≈0.92） | **70×70（1.0 正方形）** |
| 密度 | - | 几乎一致 |

**决策理由**：
- 格子完美正方形：700/10 = 1050/15 = **70px**，和手机格子密度（65.5×71）几乎一致
- 网格线贴着四边：步长 = 壳宽/COLS = 壳高/ROWS，天然对齐
- 尺寸合理：700×1050 接近 iPad mini / iPad Air 的视觉比例
- 等分数是整数：10 和 15 都是好数字，网格线分布均匀
- 和手机 6×12 一样，横向少纵向多，视觉习惯一致

### 备选方案

| 方案 | 等分 | 壳尺寸 | 格子 | 说明 |
|------|------|--------|------|------|
| 推荐 | 10×15 | 700×1050 | 70×70 ✅ | 尺寸适中，格子完美正方形 |
| 备选A | 8×12 | 560×840 | 70×70 ✅ | 完美正方形，但偏窄 |
| 备选B | 9×13 | 630×910 | 70×70 ✅ | 完美正方形，但 9 和 13 是奇数 |
| 备选C | 10×16 | 700×1120 | 70×70 ✅ | 完美正方形，偏大 |

### 9. Pad 设备响应式适配（新增）

**涉及文件**：`styles/base.css`、`styles/demo-controls.css`

**问题**：当前页面在真实 Pad 设备上打开时，布局会出问题。

**现状分析**：

当前布局只有两档媒体查询：
- `max-width: 599px` → 手机 standalone 模式（全屏，无壳）
- `min-width: 600px` → 桌面双栏模式（`layout-main` 要求 `min-width: 1440px`）

所有 Pad 设备（744px ~ 1024px 宽）都落在 `min-width: 600px` 档位，但 Pad 宽度远小于 1440px，导致：

| Pad 型号 | 视口宽度 | 效果 |
|----------|---------|------|
| iPad mini (8.3") | 744px | ❌ 横向滚动，左侧 524px + 右侧 840px 超出屏幕 |
| iPad Air/Pro 11" | 834px | ❌ 同上 |
| iPad Pro 12.9" | 1024px | ❌ 1024 < 1440，仍需横向滚动 |

**根本原因**：
- `.layout-main` 的 `min-width: 1440px` 是硬门槛
- `.left-area` 固定 `524px`，不能自适应 Pad 宽度
- `.design-notes` 最小 `840px`，进一步推高总宽需求
- 没有 `600px ~ 1439px` 的中间档媒体查询

**解决方案**（三选一）：

**方案 A：左侧缩小 + 右侧自适应（推荐）**
```css
@media (min-width: 600px) and (max-width: 1024px) {
  .layout-main { min-width: 0; }
  .left-area { width: 393px; flex: 0 0 393px; }
  .design-notes { min-width: 0; flex: 1; }
}
```
- 左侧只展示手机壳（393px），去掉额外间距
- 右侧说明栏填充剩余宽度
- 无需横向滚动

**方案 B：上下布局（竖屏 Pad 友好）**
```css
@media (min-width: 600px) and (max-width: 1024px) {
  .layout-main { flex-direction: column; align-items: center; }
  .left-area { width: 100%; flex: none; }
  .design-notes { width: 100%; min-width: 0; }
}
```
- 手机壳在上，说明栏在下
- 适合竖屏 Pad 用户

**方案 C：Pad 专属模式联动**
- 当用户切换到 Pad 模式（`.phone-shell.pad-mode`）时，自动调整双栏布局
- 左侧区域宽度根据 Pad 壳尺寸动态计算
- 右侧说明栏自适应

**关联改动**：
- `styles/base.css`：新增 `600px ~ 1024px` 媒体查询
- `styles/demo-controls.css`：Pad 模式下控制面板可能也需要调整宽度
- 如果采用方案 C，需要 JS 联动（切换 Pad 模式时同步调整布局）

## 排查结果：硬编码尺寸依赖清单

通过全局搜索 `393` 和 `852`，确认所有硬编码尺寸的位置如下：

### 硬编码尺寸清单

| # | 文件 | 行号 | 内容 | 说明 |
|---|------|------|------|------|
| 1 | `styles/base.css` | 195 | `width:393px;height:852px` | **手机壳尺寸** — 核心改动点 |
| 2 | `styles/demo-controls.css` | 55 | `width:393px` | 控制面板宽度，与手机壳同宽 |
| 3 | `styles/feature-panel.css` | 402 | `width:393px` | `.step-detail-link` 定宽匹配 demo |
| 4 | `styles/feature-panel.css` | 513 | `width:393px` | `.fp-sheet-pair-item` 定宽 |
| 5 | `styles/markdown.css` | 719-739 | `852×393` 横屏尺寸 | 表格全屏横屏模式 |
| 6 | `index.html` | 495-496 | `COLS=6, ROWS=12` | 网格等分数 |

### 各模块排查结论

| 模块 | 结论 |
|------|------|
| **engine/\*.js**（core/markdown/typewriter/sheet/player/scroll-nav/feature-jump/feature-router/ask-question） | ✅ **无任何硬编码尺寸依赖**。所有布局基于 CSS 和 DOM 流式布局，不依赖手机壳像素尺寸 |
| **scenario.js** | ✅ **无尺寸相关数据**。剧本数据（节点、对话、状态行）不绑定手机壳尺寸 |
| **engine/sheet.js** | ✅ 浮层位置计算不依赖手机壳位置 |
| **engine/ask-question.js** | ✅ 问答卡片布局基于 CSS 流式布局，不依赖手机壳尺寸 |
| **engine/feature-panel.js** | ✅ 右侧说明栏不依赖手机壳尺寸 |

### 关键发现

1. **引擎层零依赖**：所有 `engine/` 下的 JS 模块都不硬编码手机壳尺寸，Pad 模式下无需修改任何引擎代码。这是架构设计良好的体现。

2. **硬编码集中在 CSS 层**：6 处硬编码全部在 CSS 文件中，且除了 `base.css` 的壳尺寸外，其余 5 处都是"跟随手机壳宽度"的间接依赖。

3. **横屏模式已有先例**：`styles/markdown.css` 中已有 `.tbl-landscape` 横屏模式，通过 CSS class 切换壳尺寸（852×393），说明"通过 class 切换尺寸"的模式在项目中已有实践，Pad 模式可以复用同一套机制。

4. **控制面板宽度跟随策略**：`demo-controls` 宽度固定为 `393px`，Pad 模式下需要决定是等比放大（700px）还是维持原宽。建议维持原宽，因为控制面板的功能按钮不需要放大。

5. **Feature Panel 快照宽度**：`feature-panel.css` 中的两处 `393px` 是快照组件的定宽，Pad 模式下是否需要调整取决于快照内容是否要展示 Pad 尺寸的截图。

6. **横屏模式需要独立处理**：当前横屏模式（`.tbl-landscape`）硬编码了 852×393，Pad 模式下如果有横屏需求，需要定义 Pad 横屏尺寸（如 1050×700）。
