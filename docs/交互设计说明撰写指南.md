# 交互设计说明撰写指南

## 五条规则

### 1. 不做截图的事

视觉表现（颜色、图标样式、字号、间距）由截图承载，文字不再复述。截图旁边有标注的，文字只说明截图里看不到的东西（如交互行为、状态切换条件）。

### 2. 不分设计原理的席

"为什么这样做"归到「设计原理」章节，不在描述性段落里掺入决策理由。例如：

- ✓ "点选即进入下一题"
- ✗ "点选即进入下一题——因为单选有明确的作答完成信号"

### 3. 不跨段重复

一个信息在整个文档里只在一个位置讲。例如操作按钮的三态（跳过/下一步/提交）在"操作按钮"小节讲一次，后面每个题型不再重复。

### 4. 统一结构

同类内容的段落保持格式一致，让用户扫一眼就能对比差异。例如每个题型统一用两行：

- **交互**：用户操作 → 系统反馈
- **输入与选项关系**：互斥 / 共存

### 5. 说用户做的，不说系统怎么实现的

描述用户能感知到的行为，不暴露内部实现参数：

- ✓ "松手后选项落位"
- ✗ "松手后 200ms 缓动落位"
- ✓ "首次进入有引导气泡，完成首次拖拽后永久消失"
- ✗ "首次进入有循环 pop 引导动效"

---

**一句话总结**：交互说明只回答"我点了/拖了/输入了 → 然后呢"，不回答"它长什么样/为什么要这样/内部怎么实现的"。
