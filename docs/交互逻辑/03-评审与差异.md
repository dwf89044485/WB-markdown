## 十二、评审模式 vs 预览模式

| 模式                       | 推进粒度                         | 自动播放 | rail/note |
| ------------------------ | ---------------------------- | ---- | --------- |
| **评审** (`?mode=review`)  | **最小子事件**（每点 NEXT 推进 1 个）    | 可选   | 显示        |
| **预览** (`?mode=preview`) | 同样最小子事件，但全自动按 stepDelay 串行播放 | 总是自动 | 隐藏        |

**两个模式共用同一个 scenario**——区别只在驱动器。

### 12.1 评审 rail = Agent 过程类型清单 ⭐

> **rail 不是「示例剧情的目录」，rail 是「这套 demo 系统枚举的 Agent 过程类型清单」。**

示例剧情（关西旅行）只是**载体**，rail 上展示的应该是 demo 想让观众认识的过程类型——把示例换成「写论文」「做财报」也成立。

**13 个过程类型 + hierarchy**：

```
评审 rail
│
├─ ① 思考过程                      ← 演示帧 T.1 ~ T.5
│
├─ 节点1：创建待办 / 输出节点内 markdown / 联网搜索 + 待办流转
│   ├─ ② 创建待办                  ← 演示帧 1.1 ~ 1.2
│   ├─ ③ 输出节点内 markdown       ← 演示帧 1.3 ~ 1.6
│   └─ ④ 联网搜索 + 待办流转        ← 演示帧 1.7 ~ 1.12
│
├─ 节点2：生成产物 / 更新待办
│   ├─ ⑤ 生成产物（图片/视频）       ← 演示帧 2.1 ~ 2.5
│   └─ ⑥ 更新待办                  ← 演示帧 2.6 ~ 2.7（节点2 末）/ 3.6 节点3 末再演示一次
│
├─ 节点3：调用技能 / 文件操作 / 异常处理 / 执行命令 / 委派 Subagent
│   ├─ ⑦ 调用技能                  ← 演示帧 3.1
│   ├─ ⑧ 文件操作（创建/读取/编辑/搜索）  ← 演示帧 3.2 + 3.3
│   ├─ ⑨ 异常处理（错误展示 + 排障）    ← 演示帧 3.2b ⚠️ 那一刻 + 3.3
│   ├─ ⑩ 执行命令                  ← 演示帧 3.4
│   └─ ⑪ 委派 Subagent（嵌套子对话流）  ← 演示帧 3.5
│
└─ 收尾：任务总结 + 成果交付
    ├─ ⑫ 输出外层正文 markdown      ← 演示帧 F.2 ~ F.3
    └─ ⑬ 输出成果链接卡片           ← 演示帧 F.4
```

每个**过程类型**是 rail 上的一行；点击任意一行 → 跳到该过程类型对应的最小子事件区间起点。

### 12.2 评审右侧 note = 该过程类型的解说 ⭐

note 区**不是**简单的「这一帧做了什么」，而是：

> **「当前在演示什么 Agent 过程类型，这类过程在真实产品里的交互特征是什么」**

每个过程类型（① ~ ⑬）需要一段解说文字，结构如下：

```
【过程类型名】

一句话定义。

关键交互特征：
- ...
- ...

在示例中演示的帧：x.y ~ x.z（共 N 帧）。
浮层结构标准内容见附录 A.x。
```

例：当 rail 高亮在 ④ 联网搜索 + 待办流转——

> **联网搜索 + 待办流转**
> 
> Agent 在执行搜索类待办时，UI 给出两层透明度：状态行（"正在搜索网页 ›"）告诉用户「现在在搜索」，浮层（点击拉起）告诉用户「具体在搜哪几条、进度如何」。
> 
> 关键交互特征：
> 
> - 状态行文字态粗粒度（"正在搜索网页" / "搜索网页"），扫光开 / 关
> - 浮层带全局共享待办列表，逐项打勾（待办流转）
> - 浮层不带本状态行的私有事件块——主要看待办状态变化
> - 用户任意时刻点开浮层，看到的都是当下那一帧的全局快照
> 
> 在示例中演示的帧：1.7 ~ 1.12（共 6 帧）。
> 浮层结构标准内容见 [附录 A.3](./04-内容标准库.md#a3--搜索网页浮层)。

## 十四、跟当前实现的差异清单（重写依据）

| 项                      | 当前实现                                 | 应改为                                                                                           |
| ---------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------- |
| 节点头初始态                 | 一开始就是绿钩                              | RUNNING 时是 spinner，完成后才变绿钩                                                                    |
| 节点出现时机                 | 4 个节点同时出现，全收起                        | **逐个**出现；当前节点保持展开直到完成                                                                         |
| 节点 detail 内容           | 一坨静态 HTML，点击展开                       | **动态生长**，子事件逐个出现                                                                              |
| 状态行                    | 一个 button 在 detail 末尾                | **多个状态行**，11 种命名（见 [01-基础规则.md § 四](./01-基础规则.md#四状态行的状态机)）；每个有自己的态机；点击拉起浮层                   |
| **状态行命名**              | 「正创建待办」「搜索网页」「生成图片」「已生成图片，更新待办」      | 统一改为 **「正在 X ›」（跑中）/「X ›」（完成）** 模式                                                            |
| 「补充搜索：关西周游卡」节点         | 存在                                   | **删掉**                                                                                        |
| timing-bar             | agent-shell 出现时就渲染了                  | **改到最后**，所有节点跑完之后才出现                                                                          |
| 「思考过程 ›」               | 是 toggle button，点击折叠 steps-list（目录式） | **改成独立状态行**（不属于任何节点），点击拉起浮层；不是目录入口                                                            |
| 「思考过程」浮层内容             | 不存在                                  | 「思考过程」标题 + 🧠 + 思考 markdown                                                                   |
| **浮层标题**               | 永远是「过程」                              | 改成 **跟点击的状态行同名**（10 种）                                                                        |
| **浮层多帧**               | 一个状态行 = 一份静态 HTML                    | **同一文字态内部，浮层快照可以有多帧**——后台进度推进，浮层逐帧切换                                                          |
| **浮层事件块累积逻辑**          | 累积式                                  | **不累积**——每个浮层只展示自己当前状态行的事件块；跨状态行/跨节点不累积                                                       |
| **浮层待办列表**             | 跟事件块混作一团                             | **独立成一层、全局共享**——一份 7 条待办清单，状态在所有「带待办列表的浮层」里同步流转；只有 5 个浮层带待办列表（创建待办/搜索网页/生成图片/更新待办×2）          |
| 扫光效果                   | 不存在                                  | 单行文字横向高亮 animation                                                                            |
| **节点1 数量**             | 1 个步骤行                               | 14 个最小子事件                                                                                     |
| **节点2 数量**             | 1 个步骤行                               | 9 个最小子事件                                                                                      |
| **节点3 数量**             | 1 个步骤行（含静态文档预览图）                     | **30 个最小子事件**，演示 6 类过程：调用技能/文件操作/异常处理/执行命令/委派 Subagent/更新待办                                   |
| **节点内 vs 外层 markdown** | 没区分                                  | **节点内 markdown** 属于节点 detail；**外层正文 markdown** 属于收尾段；样式相同但归属不同                                |
| 链接卡片                   | 不存在                                  | 收尾段最末出现「查看日本关西家庭旅行方案 v1.0」蓝色链接                                                                |
| **评审 rail**            | 已有，但每行映射的是粗粒度示例剧情节点                  | 重写成 **13 个 Agent 过程类型清单**（① ~ ⑬，见 § 12.1）                                                     |
| **评审 note**            | 来源不固定；只讲「这一帧做了什么」                    | 来自本目录；讲「**当前在演示什么过程类型 + 这类过程在真实产品里的交互特征**」+ 链接到 [附录 A.x](./04-内容标准库.md#附录-a--浮层内容标准库) 的浮层结构标准 |

- [ ] 委派 Subagent 浮层里的「嵌套子对话流」——是否需要支持子对话流内部的扫光、子状态行点击？还是 demo 简化成静态展示？倾向**静态简化**（嵌套对话流是只读的回放材料，不再深入）。
