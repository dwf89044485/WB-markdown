### 1.3 当前实现的关键问题

| 问题                      | 描述                                      |
| ----------------------- | --------------------------------------- |
| **beat 粒度错误**           | 9 个粗粒度 beat vs 规范要求的 63 个最小子事件          |
| **节点一次性铺开**             | 4 个节点在 agent-shell 出现时同时渲染，而非逐个出现       |
| **节点无状态机**              | 节点头一开始就是绿钩，没有 spinner → 绿钩 的状态转换        |
| **节点无自动塌缩**             | 节点始终展开，没有 RUNNING → DONE 自动塌缩           |
| **状态行非独立组件**            | 状态行混在 detailHtml 里作为 HTML 字符串，无法独立渲染/切换 |
| **状态行命名不统一**            | 各种非规范命名：正创建待办 / 已生成图片，更新待办              |
| **无扫光效果**               | shimmer 完全缺失                            |
| **浮层标题固定**              | 标题永远是"过程"，而非 10 种动态标题                   |
| **浮层事件块累积**             | 所有历史事件堆在一起，没有"不累积"逻辑                    |
| **浮层待办无独立层**            | 待办列表跟事件块混杂，不是独立的全局共享层                   |
| **无快照语义**               | 点击历史状态行看到的是当前状态，不是当时快照                  |
| **思考过程是 toggle button** | 应该是独立状态行，点击拉起浮层                         |
| **timing-bar 位置错误**     | agent-shell 出现时就渲染，应该全部跑完后才出现           |
| **评审 rail 粗粒度**         | 9 行剧情节点 vs 13 个 Agent 过程类型              |
| **无链接卡片**               | 收尾段的蓝色链接卡片缺失                            |

## 二、规范要求的完整梳理

### 2.1 最小子事件（beats）

规范要求 **63 个最小子事件**，完整清单见 [05-beats清单.md](./05-beats清单.md)。

**分段统计**：

- 用户气泡：1 个（b00）
- Agent 进场 + 思考：5 个（b01-b05）
- 节点1（任务理解与分解）：14 个（b06-b19）
- 节点2（生成图片）：9 个（b20-b28）
- 节点3（整合输出）：30 个（b29-b58）
- 收尾段：4 个（b59-b62）

### 2.2 状态行体系

**11 个状态行**，统一命名规则：

- 跑中：「正在 X ›」+ 扫光开
- 完成：「X ›」+ 扫光关

| ID                | 跑中态             | 完成态           | 所属位置      |
| ----------------- | --------------- | ------------- | --------- |
| think             | 正在思考 ›          | 思考过程 ›        | 独立（节点前）   |
| create-todo       | 正在创建待办 ›        | 创建待办 ›        | 节点1       |
| search-web        | 正在搜索网页 ›        | 搜索网页 ›        | 节点1       |
| gen-image         | 正在生成图片 ›        | 生成图片 ›        | 节点2       |
| update-todo       | 正在更新待办 ›        | 更新待办 ›        | 节点2末/节点3末 |
| call-skill        | 正在调用技能 ›        | 调用技能 ›        | 节点3       |
| create-file       | 正在创建文件 ›        | 创建文件 ›        | 节点3       |
| search-file       | 正在搜索文件 ›        | 搜索文件 ›        | 节点3       |
| exec-cmd          | 正在执行命令 ›        | 执行命令 ›        | 节点3       |
| delegate-subagent | 正在委派 Subagent › | 委派 Subagent › | 节点3       |

### 2.3 节点状态机

```
IDLE(不渲染) ─────► RUNNING(spinner+展开) ─────► DONE(绿钩+塌缩)
                         │                           │
                    手动点头↓                    手动点头↓
                  USER_COLLAPSED              USER_EXPANDED
                  (收起但内部继续)             (展开静态历史)
```

### 2.4 浮层双层模型

```
┌─────────────────────────────────────┐
│ 浮层标题（动态，10 种）              │
├─────────────────────────────────────┤
│ 事件块层（私有，不累积）             │
│ - 只显示当前状态行的事件块           │
│ - 跨状态行不累积                     │
├─────────────────────────────────────┤
│ 待办列表层（全局共享，5个浮层带）    │
│ - 7 条待办，全局共享一份             │
│ - 状态实时同步流转                   │
└─────────────────────────────────────┘
```

**带待办列表的 5 个浮层**：

1. 创建待办
2. 搜索网页
3. 生成图片
4. 更新待办（节点2末）
5. 更新待办（节点3末）

### 2.5 快照语义（时光倒流）

点击已完成的状态行 → 浮层显示该状态行**最末态时刻的全局快照**：

- 事件块：该状态行的事件块（不是当前累积）
- 待办列表：**回到那一刻的状态**（不是当前最新）

### 2.6 评审 rail

**13 个 Agent 过程类型**（不是 9 个剧情节点）：

```
① 思考过程
节点1
  ② 创建待办
  ③ 输出节点内 markdown
  ④ 联网搜索 + 待办流转
节点2
  ⑤ 生成产物
  ⑥ 更新待办
节点3
  ⑦ 调用技能
  ⑧ 文件操作
  ⑨ 异常处理
  ⑩ 执行命令
  ⑪ 委派 Subagent
收尾
  ⑫ 输出外层正文 markdown
  ⑬ 输出成果链接卡片
```

#### 4.2.2 reducer

```js
function applyAction(state, action) {
  switch (action.type) {
    case 'node_start':
      return {
        ...state,
        nodes: {
          ...state.nodes,
          [action.nodeId]: { ...state.nodes[action.nodeId], status: 'running' }
        }
      };

    case 'node_collapse':
      return {
        ...state,
        nodes: {
          ...state.nodes,
          [action.nodeId]: { ...state.nodes[action.nodeId], status: 'done' }
        }
      };

    case 'status_start':
      return {
        ...state,
        statusLines: {
          ...state.statusLines,
          [action.statusLineId]: {
            state: 'running',
            events: [],
            beatIndex: state.beatIndex,
            nodeId: action.nodeId
          }
        },
        nodes: action.nodeId ? {
          ...state.nodes,
          [action.nodeId]: {
            ...state.nodes[action.nodeId],
            statusLineIds: [...state.nodes[action.nodeId].statusLineIds, action.statusLineId]
          }
        } : state.nodes
      };

    case 'status_done':
      return {
        ...state,
        statusLines: {
          ...state.statusLines,
          [action.statusLineId]: {
            ...state.statusLines[action.statusLineId],
            state: 'done',
            doneBeatIndex: state.beatIndex
          }
        }
      };

    case 'todo_update':
      return {
        ...state,
        todos: state.todos.map(t => 
          t.id === action.todoId ? { ...t, status: action.status } : t
        )
      };

    case 'event_add':
      const sl = state.statusLines[action.statusLineId];
      return {
        ...state,
        statusLines: {
          ...state.statusLines,
          [action.statusLineId]: {
            ...sl,
            events: [...sl.events, action.event]
          }
        }
      };

    case 'think_chunk':
      return {
        ...state,
        thinkChunks: [...state.thinkChunks, action.chunk]
      };

    case 'md_chunk':
      if (action.nodeId) {
        return {
          ...state,
          nodes: {
            ...state.nodes,
            [action.nodeId]: {
              ...state.nodes[action.nodeId],
              mdChunks: [...state.nodes[action.nodeId].mdChunks, action.chunk]
            }
          }
        };
      }
      return {
        ...state,
        summaryChunks: [...state.summaryChunks, action.chunk]
      };

    default:
      return state;
  }
}

function applyBeat(state, beat) {
  let newState = { ...state, beatIndex: state.beatIndex + 1 };
  for (const action of (beat.actions || [])) {
    newState = applyAction(newState, action);
  }
  return newState;
}

function getStateAt(scenario, beatIndex) {
  const initial = createInitialState(scenario);
  return scenario.beats
    .slice(0, beatIndex + 1)
    .reduce(applyBeat, initial);
}
```

```js
function getSnapshotForStatusLine(scenario, statusLineId, currentBeatIndex) {
  // 找到该状态行的 doneBeatIndex（如果已完成）或 currentBeatIndex
  const state = getStateAt(scenario, currentBeatIndex);
  const sl = state.statusLines[statusLineId];
  if (!sl) return null;

  const targetBeatIndex = sl.state === 'done' ? sl.doneBeatIndex : currentBeatIndex;
  const snapshotState = getStateAt(scenario, targetBeatIndex);

  return {
    title: scenario.statusLineMeta[statusLineId].done.replace(' ›', ''),
    events: snapshotState.statusLines[statusLineId]?.events || [],
    todos: scenario.statusLineMeta[statusLineId].hasTodo ? snapshotState.todos : null
  };
}
```

### 4.4 渲染器设计

```js
class Renderer {
  constructor(container, state) {
    this.container = container;
    this.state = state;
  }

  // 根据 state 差异更新 DOM
  update(prevState, newState) {
    // 节点状态变化
    for (const nodeId of Object.keys(newState.nodes)) {
      const prev = prevState.nodes[nodeId];
      const curr = newState.nodes[nodeId];
      if (prev.status !== curr.status) {
        this.updateNodeStatus(nodeId, curr.status);
      }
    }

    // 状态行状态变化
    for (const slId of Object.keys(newState.statusLines)) {
      const prev = prevState.statusLines[slId];
      const curr = newState.statusLines[slId];
      if (!prev) {
        this.renderStatusLine(slId, curr);
      } else if (prev.state !== curr.state) {
        this.updateStatusLineState(slId, curr.state);
      }
    }

    // 待办状态变化
    if (JSON.stringify(prevState.todos) !== JSON.stringify(newState.todos)) {
      this.updateTodos(newState.todos);
    }
  }

  updateNodeStatus(nodeId, status) {
    const el = this.container.querySelector(`[data-node-id="${nodeId}"]`);
    if (el) {
      el.dataset.status = status;
      if (status === 'done') {
        // 自动塌缩动画
        el.classList.add('collapsing');
        setTimeout(() => el.classList.remove('collapsing'), 300);
      }
    }
  }

  updateStatusLineState(slId, state) {
    const el = this.container.querySelector(`[data-status-line-id="${slId}"]`);
    if (el) {
      el.dataset.state = state;
      const meta = this.scenario.statusLineMeta[slId];
      el.querySelector('.status-line-text').textContent = 
        state === 'running' ? meta.running : meta.done;
    }
  }
}
```

### 4.5 播放器设计

```js
class Player {
  constructor(scenario, renderer, panels) {
    this.scenario = scenario;
    this.renderer = renderer;
    this.panels = panels;
    this.state = createInitialState(scenario);
    this.beatIndex = -1;
  }

  async next(opts = {}) {
    if (this.beatIndex >= this.scenario.beats.length - 1) return false;

    this.beatIndex++;
    const beat = this.scenario.beats[this.beatIndex];
    const prevState = this.state;
    this.state = applyBeat(this.state, beat);

    // 更新 DOM
    this.renderer.update(prevState, this.state);

    // 执行 render 指令（打字机等）
    for (const piece of (beat.render || [])) {
      if (opts.instant) {
        this.renderer.renderInstant(piece);
      } else {
        await this.renderer.renderAnimated(piece);
      }
    }

    // 更新 rail 和 note
    this.panels.highlightRail(this.beatIndex);
    this.panels.showNote(beat);

    // 如果浮层打开，更新浮层内容
    if (this.state.panel.isOpen) {
      this.updateOpenPanel();
    }

    return true;
  }

  prev() {
    if (this.beatIndex < 0) return false;

    // 回退状态
    this.beatIndex--;
    this.state = getStateAt(this.scenario, this.beatIndex);

    // 重建 DOM（简单方案：清空重渲染）
    this.renderer.rebuildFromState(this.state);

    return true;
  }

  updateOpenPanel() {
    const { statusLineId } = this.state.panel;
    const snapshot = getSnapshotForStatusLine(
      this.scenario, 
      statusLineId, 
      this.beatIndex
    );
    this.renderer.updatePanel(snapshot);
  }
}
```
