# Demo 与评审页交接文档 v0.1

> 本文面向本地开发和演示团队，提供可落地的 mock 场景定义、数据结构和评审路径。规范与数据分离——规范见 01/02 文档，本文只负责"演什么"和"怎么评"。

---

## 一、Demo 场景与目标

### 1.1 场景：关西家庭旅行方案

延续当前 mock 的完整故事线：

- **用户委托**：规划一次 2026 年 9 月 18 日–24 日的关西家庭旅行，4 人同行，含身体约束和预算约束。
- **Agent 执行**：完整经历思考 → 任务分解 → 待办创建 → 联网搜索 → 图片生成 → 文档整合 → 异常修复 → Subagent 委派 → 结果交付。
- **交付物**：一份结构化旅行方案 PDF + 方案概要 + 成果链接。

### 1.2 Demo 的核心目的

**不是展示旅行方案的内容，而是展示 Agent 系统的 13 种过程类型如何在对话流中被渐进式披露。**

| 编号 | 过程类型 | 出现在 | 观众要带走的感觉 |
|------|---------|--------|----------------|
| ① | 思考过程 | 节点1 之前 | Agent 不是黑盒，它在理解我 |
| ② | 创建待办 | 节点1 | 复杂任务被拆成可追踪的子任务 |
| ③ | 输出节点内 markdown | 各节点 | 过程本身也是结构化的信息 |
| ④ | 联网搜索 | 节点1 | 实时信息正在流入 |
| ⑤ | 待办流转 | 贯穿节点1~3 | 任务在推进，有进度感 |
| ⑥ | 生成产物 | 节点2 | AI 正在创造可视化内容 |
| ⑦ | 更新待办 | 节点2、3 末 | 里程碑被标记 |
| ⑧ | 调用技能 | 节点3 | Agent 能调用专业工具 |
| ⑨ | 文件操作 | 节点3 | 能看到文件级别的操作 |
| ⑩ | 异常处理 | 节点3 | 出错不可怕，能看到修复过程 |
| ⑪ | 执行命令 | 节点3 | 深入到命令级调试 |
| ⑫ | 委派 Subagent | 节点3 | 复杂问题 Agent 能自我分工 |
| ⑬ | 外层正文 markdown | 收尾段 | 结果像验收单一样干净 |
| ⑭ | 成果链接 | 收尾段 | 交付物是实体对象，可点击 |

### 1.3 Demo 运行时参数

```
stepDelay:     470ms
frameDelay:    520ms
autoStartDelay: 420ms
tokensPerSecond: 200
```

速度控制由 `#ctrlSpeedSlider`（range 20~1000, step 10）统一管理，`typeIntervalForChunk()` 和 `playbackDelay()` 同步响应。

### 2.2 待办清单（全局唯一，顺序固定）

```
① 任务理解与分解：明确需求、约束和输出格式
② 联网搜索：签证/入境政策、交通卡、景点开放情况
③ 天气趋势与穿衣建议
④ 汇率与预算换算
⑤ 城际交通与路线时间
⑥ 生成关西主要地点图片
⑦ 整合信息，输出完整旅行方案文档
```

流转顺序：
- 节点1：① 创建 → ① ✅ → ② 🔄 → ... → ⑤ ✅ → ⑥ 🔄
- 节点2：⑥ ✅ → ⑦ 🔄
- 节点3：⑦ ✅

### 2.3 思考过程帧（3 帧，T.a / T.b / T.c）

| 帧 | 标题 | 内容要点 |
|----|------|---------|
| T.a | 需求识别 | 用户画像、约束提炼、任务复杂度判断 |
| T.b | 过程规划 | 7 个阶段的任务拆分，各阶段目标陈述 |
| T.c | 执行策略 | 约束落地策略——膝盖问题、生食过滤、汇率弹性等 |

运行时：T.2「正在思考 ›」出现 → 后台逐帧推进 → T.4「思考过程 ›」定格。

用户可在 T.2 ~ T.4 任意时刻点击，看到该时刻的 markdown 截止内容。

## 三、评审页 Step-by-Step 脚本

### 3.1 评审页目标

评审页不是"看一遍 demo"，而是**按设计的节奏暴露关注点**，让评审者在每个阶段看到应该看到的东西。

### 3.2 步进路径（共 15 步）

| 步 | 阶段 | 应出现的要素 | 评审关注点 |
|----|------|------------|----------|
| 1 | 初始态 | 手机壳、导航栏、输入框、空对话区 | 整体视觉骨架是否干净 |
| 2 | 用户发送消息 | 用户气泡出现（瞬间） | 气泡样式、头像、时间戳 |
| 3 | Agent 进场 | Agent header 出现（头像+名字） | 品牌标识是否清晰 |
| 4 | 思考过程 | 「正在思考 ›」行 + 扫光 | 思考不是黑盒；状态行命名是否友好；扫光是否只覆盖文字行 |
| 5 | 思考浮层（可选点击） | 浮层标题「思考过程」+ 🧠 卡片 + markdown 打字机 | 三段式思考（需求识别→过程规划→执行策略）是否可感知；打字机速度是否合适 |
| 6 | 节点1 头出现 | spinner + 「任务理解与分解：明确需求、约束和输出格式」 | 节点头命名是否描述性；不会出现灰圆（IDLE态不渲染） |
| 7 | 创建待办 | 「正在创建待办 ›」→「创建待办 ›」 | 状态行命名统一性；扫光开关时机 |
| 8 | 节点内 markdown | h2 + 目标 + 约束 + 表格 逐行打字机 | 内容可读性；表格渲染；打字机是否跟随 tokensPerSecond |
| 9 | 联网搜索 | 「正在搜索网页 ›」→ 浮层逐帧推进 →「搜索网页 ›」 | 浮层高度自动展开（40%→内容适配）；去重机制；搜索 outputs 逐条追加；待办列表是否全局同步 |
| 10 | 节点1 自动塌缩 | spinner → 绿钩，detail 收起 | 塌缩时机是否自然；已完成节点是否弱化 |
| 11 | 节点2 生成图片 | 节点2 头 → markdown →「正在生成图片 ›」→ 图片事件块逐帧 → 塌缩 | 事件块不累积规则——浮动层内只看到当前状态行的事件；图片生成是否有推进感 |
| 12 | 节点3 复杂过程 | 调用技能 → 文件操作 → 异常出现 → 修复过程 → 命令执行 → Subagent 委派 → 更新待办 | 异常是否在浮层内轻量展示；修复链条是否可追溯；Subagent 浮层内嵌子对话流是否合理；**快照语义**：回点已完成状态行看到的是那一刻的切片 |
| 13 | timing-bar 出现 | 「任务耗时 19m 40s」+ chevron | **timing-bar 只在全部节点结束后出现**；不是一开始就占位 |
| 14 | 结果交付态 | h2「总结」+ 方案概要打字机 + 链接卡片 | 结果是否干净优先；过程是否已折叠为入口；交付物是否是可点击的对象 |
| 15 | 过程追溯 | 点击 timing-bar / 执行过程入口 → 展开节点 → 点击状态行 → 浮层 → 逐层关闭 | 逐级下钻链路是否顺畅：执行过程 → 节点 → 事件详情 → 原始记录；关闭浮层后位置是否保持 |

### 3.3 每步的设计意图卡片（示例）

**Step 4：思考过程**

```
设计意图：
  让用户第一时间知道 Agent 不是空转，而是在"理解我"。
  思考过程三段式：需求识别 → 过程规划 → 执行策略，
  对应人类解决问题的正常思维顺序。

评审关注点：
  [ ] 思考过程文字是否像"产品化的任务理解"，而非原始模型思考
  [ ] 三段式内容是否让用户感到"被认真对待"
  [ ] 扫光是否只覆盖文字行，没有过度蔓延
  [ ] 思考浮层打开后，markdown 打字机是否流畅
```

**Step 9：联网搜索**

```
设计意图：
  展示"信息流入"的过程感。4 条搜索逐条完成，
  每条对应一个待办状态流转（②→③→④→⑤）。
  搜索 outputs 逐条追加，制造"后台正在查询"的实感。

评审关注点：
  [ ] 浮层打开时默认高度 40%，内容溢出后是否自动展开
  [ ] 待办列表在 F1.c ~ F1.g 之间是否实时同步推进
  [ ] 10 条搜索 outputs 是否以合理间隔逐条出现
  [ ] 已完成后回点「搜索网页 ›」，看到的是 F1.g 快照（10 条outputs 全在，待办①~⑤全✅）
  [ ] 浮层事件块是否只有搜索相关事件（不累积创建待办的事件块）
```

**Step 12：节点3 复杂过程**

```
设计意图：
  这是 demo 最复杂的段落，意图展示：Agent 运行中出错了怎么办。
  异常（文件创建失败）→ 排查（搜索文件）→ 修复（编辑文件）→ 命令尝试 → 委派子 Agent → 最终恢复。
  整个过程让观众理解：透明不是避免错误，而是让错误可追溯。

评审关注点：
  [ ] ⚠️ 文件创建失败是否以 warn 色轻量展示，而非红色 panic
  [ ] 修复链条（失败 → 创建 → 读取 → 编辑 → 搜索 → 编辑 → 命令 ×3 → Subagent）是否逻辑清晰
  [ ] Subagent 浮层内的嵌套子对话流是否一眼可辨是"子级"
  [ ] 节点内 markdown 是否及时解释当前动作（"这个文件还残留 )))" / "没有成功..." / "文档已成功生成"）
  [ ] 节点3 内部浮层是否**不带待办列表**（待办属于全局，不应出现在排障细节里）
  [ ] 只有最后的「更新待办 ›」浮层才带回待办列表，且 ⑦ 从 🔄→✅
```

**Step 13：timing-bar**

```
设计意图：
  timing-bar 是收尾段的"封顶"，标志"全部结束了"。
  它只在所有节点完成后出现，不是开场占位——这是过程到结果切换的视觉锚点。

评审关注点：
  [ ] timing-bar 是否在节点3 塌缩后才出现
  [ ] 不是开头就有 timing-bar（若有，需纠正）
  [ ] 时间文本格式是否统一（"执行过程 19m 40s"）
  [ ] 是否可点击，点击后展开执行过程回顾
```

**Step 15：过程追溯**

```
设计意图：
  验证"渐进式披露"是否可逆——完成态用户能一层一层查回过程。
  追溯路径：结果 → 执行过程 → 节点 → 事件 → 原始记录。
  各级都有明确的返回路径。

评审关注点：
  [ ] 点击 timing-bar 或「执行过程 19m 40s」后，是否展开所有节点列表
  [ ] 点击节点头后，detail 是否展开并显示该节点所有状态行
  [ ] 点击状态行后，浮层标题是否 = 状态行同名
  [ ] 浮层内的事件块是否为该状态行生命周期的快照（不累积其他状态行）
  [ ] 待办列表在带待办的浮层中是否为该时刻的全局状态（时光倒流语义）
  [ ] 关闭浮层后是否回到对话流的正确位置
  [ ] 收起执行过程后，结果区是否仍然干净前置
```

## 四、评审 Checklist（Demo 验收）

### 4.1 基础规则验证

- [ ] **节点状态机**：同一时刻最多一个 RUNNING 节点；RUNNING 时节点头为 spinner（蓝）；DONE 时为绿钩；IDLE 态不渲染（无灰圆）
- [ ] **自动塌缩**：节点最后一个子事件完成后自动塌缩；首次完成后才触发，后续用户手动展开/收起不再自动
- [ ] **状态行命名**：严格使用 11 个状态行字典中的跑中态/完成态，禁止自行发明
- [ ] **扫光规则**：只覆盖「正在 X ›」文字行 + chevron，不覆盖整个 row 或节点头
- [ ] **timing-bar 时机**：全部节点跑完后才出现，不是开头先渲染

### 4.2 浮层规则验证

- [ ] **标题同名**：浮层标题 = 状态行同名（思考过程/创建待办/搜索网页...）
- [ ] **事件块不累积**：每个浮层只展示当前状态行生命周期内的事件，不跨状态行累积
- [ ] **待办列表全局同步**：同一份 7 条待办在所有带待办浮层中实时同步
- [ ] **快照语义**：点击已完成状态行，浮层显示该状态行完成时刻的切片（事件块 + 待办状态均定格）
- [ ] **高度管理**：默认 40%，内容溢出自动展开到适配高度（上限 80%），超过后 body 可滚动
- [ ] **拖拽行为**：40% 态上拖展开/下拖关闭；80% 态+顶部时下拖折叠；内容滚动时不拦截手势
- [ ] **关闭方式**：点击遮罩背景、点击关闭按钮、下拖超 40px 阈值

### 4.3 内容加载验证

- [ ] **加载顺序**：Run 状态 → 阶段 → 节点 → 事件 → 工具详情 → 原始记录 → 结果
- [ ] **节点渐进出现**：不一次性堆满，按执行顺序逐步出现
- [ ] **内容打字机**：markdown 使用 DOM 节点级打字机，跟随 tokensPerSecond
- [ ] **搜索 outputs 逐条追加**：条间间隔 `frameDelay × 0.25`，滚动跟随

### 4.4 速度控制验证

- [ ] **Slider 范围**：20 ~ 1000，步进 10
- [ ] **当前值显示**：`#ctrlSpeedValue` 实时显示
- [ ] **打字机响应**：`typeIntervalForChunk()` 实时读取 slider 值
- [ ] **步进间隔响应**：`playbackDelay()` 按 `200 / tps` 缩放 frameDelay 和 stepDelay
- [ ] **调速对两者同时生效**

### 4.5 交互链路验证

- [ ] `执行过程 → 节点 → 状态行 → 浮层 → 原始记录` 链路完整
- [ ] 各级都有返回路径（浮层关闭钮、返回上一段、遮罩点击关闭）
- [ ] 关闭浮层后不对话流位置不跳变
- [ ] 收起执行过程后结果区仍然前置

## 五、已知限制与后续迭代方向

### 5.1 当前 mock 的简化

| 简化项 | 真实系统 | Mock 当前 |
|--------|---------|----------|
| 思考过程 | 真实模型推理流 | 预编排 3 帧 |
| 联网搜索 | 真实 API 返回 | 预写 10 条摘要 |
| 图片生成 | 真实生图 API | 只有事件块，无真实图片 |
| 文件操作 | 真实文件系统 | 纯事件块展示 |
| 命令执行 | 真实 shell | 纯事件块展示 |
| Subagent | 真实子 Agent | 卡片 + 嵌套子对话流示意 |
| 时间 | 真实耗时 | 固定显示 "19m 40s" |

### 5.2 后续可扩展

- **更多异常分支**：当前只展示了文件创建失败 → 修复，可扩展网络超时、权限不足、用户取消等分支
- **用户确认节点**：当前 demo 没有展示"等待用户确认"场景，可补充"发送邮件/覆盖文件"等确认节点
- **多交付物**：当前只有一份 PDF，可展示多交付物列表（PDF + 表格 + 邮件草稿）
- **部分完成**：当前全部完成，可模拟某个节点部分完成（如天气信息不可用）
