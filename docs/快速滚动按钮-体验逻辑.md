# 快速滚动按钮 — 体验逻辑（用户视角）

> 本文描述用户面对 ↑ ↓ 按钮时的操作感受和预期行为，帮助设计师/PM 评审交互是否自然。

---

## 1. 按钮长什么样

- 两个圆角图标按钮，水平排列在输入框上方
- ↑ 朝上箭头 / ↓ 朝下箭头，一眼能看出方向
- 两个按钮之间有间隔，手指不会误触
- 输入框没激活时按钮也在那，随时可用

### 按钮位置会随数量变化

- **只出现一个按钮时**：它居中在输入框上方
- **两个按钮都出现时**：分列左右，各占据一侧

从"一个"到"两个"或从"两个"到"一个"切换时，按钮不是瞬间跳过去，而是平滑移动到新位置。比如你从底部向上滚，↑ 按钮逐渐出现并与 ↓ 按钮分开——↓ 按钮往左滑、↑ 按钮往右滑，像两个按钮"让开"了中间位置。

## 2. 什么时候能看见按钮

按钮的显隐只取决于**滚动位置**——有没有内容可看，而不是有没有"下一轮"：

| 滚动位置 | ↑ 向上按钮 | ↓ 向下按钮 |
|---|---|---|
| 对话在顶部，没有更早的内容 | 消失 | 可见 |
| 翻到中间，上下都有内容 | 可见 | 可见 |
| 对话在底部，没有更新的内容 | 可见 | 消失 |

## 3. 按一下 ↑ 会怎样

↑ 的设计原则是：**优先带你回去看上一轮说了什么，但如果你正在读的东西还没看完，先把你拉回当前这轮的开头。**

具体来说：

| 你当前看到的情况 | 按一下 ↑ 的效果 |
|---|---|
| 你在 Agent 的回复内容中间，屏幕上看不到上一条 Agent 回复的任何内容 | 回到这一轮你提问的地方（你的那条消息出现在屏幕最上方） |
| 你已经往回翻了一点，屏幕顶部露出了上一条 Agent 回复的末尾 | 直接跳到上一轮的"你问了什么"（你的消息出现在最上方） |
| 两轮交界处——上一条回复的尾巴和你的下一条提问都在屏幕里 | 跳到上一轮的你问了什么（因为当前提问你已经看到了） |
| 你已经在最早一轮，没有更早的对话了 | 按钮消失了，按不了 |

## 4. 按一下 ↓ 会怎样

↓ 很简单：**跳到下一轮的开头。**

不管你当前在看什么位置，按一下 ↓，下一轮你的提问就会出现在屏幕最上方。如果已经是最后一轮，按一下 ↓ 会直接滚到底部。如果已经在最底部，按钮消失。

## 5. 双击会怎样

↑ 和 ↓ 各自独立判断双击，互不影响。

| 你的操作节奏 | 触发的效果 |
|---|---|
| 快速连点 ↑ 两次（间隔很短，像双击鼠标的感觉） | 直接跳到**对话流最开头**（最早一轮你的提问出现在顶部） |
| 快速连点 ↓ 两次 | 直接跳到**对话流最末尾**（最新一轮顶部对齐屏幕） |
| 点了 ↑ 之后，犹豫了一下再点一次（比双击慢一点，但感觉还在"我想快速操作"的范围） | 先执行一次正常的 ↑ 翻页，同时在按钮上方**弹出一行提示**："双击 ↑ 可跳转对话顶部" |
| 间隔很久才点第二次 | 就是两次独立的翻页 |

## 6. 弹出提示长什么样

- 出现在按钮正上方
- 灰色圆角小浮层
- ↑ 按钮上方显示："双击 ↑ 可跳转对话顶部"
- ↓ 按钮上方显示："双击 ↓ 可跳转对话底部"
- 出现后两三秒自己消失
- 同一个提示不会反复弹

## 7. 几个用户可能会遇到的情况

| 场景 | 结果 |
|---|---|
| 对话在最开头，快速双击 ↑ | 不做任何事（本来就在顶部） |
| 快速先点 ↑ 再快速点 ↓（中间隔很短） | 各自算各自的，↑ 翻上、↓ 翻下，不触发跳顶/跳底 |
| Agent 正在打字输出中，我点按钮 | 可以点，正常翻页 |
| 在全屏看表格，想点按钮 | 按钮隐藏了，退回到正常模式才能用 |
