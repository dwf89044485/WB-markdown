# 快速滚动按钮 — 实现逻辑（开发者视角）

> 本文描述 ↑ ↓ 按钮在具体代码层面的状态判断、滚动计算、边界处理。实现前必读。
> 源码：`engine/scroll-nav.js` · 样式：`styles/base.css`（`.scroll-nav` 段）

---

## 1. 数据结构

### 1.1 全局状态对象 `SN`

```js
const SN = {
  turns: [],           // [{ userMsg, agentMsg }]
  nav: null,           // #scrollNav
  upBtn: null,         // #scrollUp
  downBtn: null,       // #scrollDown
  conv: null,          // .conversation
  upState: {
    lastClickTime: 0,       // 上次点击时间（performance.now()）
    tooltipTimer: null,     // 延迟弹提示的定时器
    dblclickGraduated: false, // 双击毕业标记
    rapidStreak: 0,         // 连续快速点击计数
  },
  downState: { /* 同 upState */ },
  scrollTicking: false,
  isTblFullscreen: false,
};
```

### 1.2 对话轮次索引

```js
turns = [
  { userMsg: HTMLElement, agentMsg: HTMLElement },
  ...
]
```

- **`userMsg` 选择器**：`.user-msg-wrap:not(.is-hidden)`
- **`agentMsg` 选择器**：`.agent-msg:not(.is-hidden)`
- 配对方式：第 N 个 user-msg-wrap 与第 N 个 agent-msg 组成一轮
- **重建时机**：`rebuildScrollNav()` / 播放新增一轮后

### 1.3 当前轮次判定

遍历 `turns`，取每个 `userMsg` 的 `offsetTop`（相对于 `.conversation`），第一个 `offsetTop >= scrollTop - 1` 的即为当前轮。容差 1px 避免浮点精度问题。

## 2. 按钮显隐逻辑

### 2.1 判断条件

```js
scrollTop    = conversation.scrollTop
scrollBottom = scrollTop + conversation.clientHeight
scrollHeight = conversation.scrollHeight

showUp   = scrollTop > 5
showDown = scrollBottom < scrollHeight - 5
```

5px 容差避免浮点精度/1px 滚动残留误判。

### 2.2 触发时机

- `.conversation` 的 `scroll` 事件（requestAnimationFrame 节流）
- 播放引擎新增一轮后（`rebuildScrollNav()`）
- 表格全屏状态变化

### 2.3 入场动画

从隐藏变显示时，添加 `is-appearing` class（`opacity: 0`），双 rAF 后移除，CSS transition 驱动 0.2s 淡入。

消失时不做动画，直接 `display: none`。

### 2.4 预判模式（skipEntrance）

`smoothScrollTo()` 在触发滚动前，会**预判**目标位置下按钮的显隐状态，提前瞬间切换按钮可见性（跳过入场动画）。这样滚动结束时按钮已经完全可见，避免"滚完了按钮才淡入"的割裂感。

## 3. 布局与定位

### 3.1 DOM 结构

```html
<div class="scroll-nav" id="scrollNav">
  <button class="scroll-nav-btn" id="scrollUp">...</button>
  <button class="scroll-nav-btn" id="scrollDown">...</button>
</div>
```

`#scrollNav` 位于 `.composer` 上方，在 `index.html` 中。

### 3.2 CSS 定位

```css
.scroll-nav {
  position: relative;
  height: 0;            /* 不占空间，靠子元素绝对定位溢出显示 */
  overflow: visible;
  flex-shrink: 0;
  z-index: 20;
  pointer-events: none; /* 容器不拦截事件 */
}

.scroll-nav-btn {
  pointer-events: auto;
  position: absolute;
  right: 8px;
  width: 36px;
  height: 36px;
  /* 磨砂玻璃效果 */
  background: rgba(255, 255, 255, 0.4);
  backdrop-filter: blur(3px);
}

#scrollUp   { bottom: calc(10px + 36px + 8px); }  /* ↓ 上方 44px */
#scrollDown { bottom: 10px; }                       /* 紧贴输入框上方 10px */
```

**关键设计决策**：

- 容器 `height: 0` + 子元素绝对定位 → 按钮浮在输入框上方，不占用文档流空间
- 两个按钮各自绝对定位 → **一个消失不影响另一个位置**（竖排设计的核心优势）
- `pointer-events: none` 容器 + `auto` 按钮 → 避免容器拦截点击事件

### 3.3 Tooltip 定位

```css
.sn-tooltip {
  position: absolute;
  right: calc(100% + 8px);  /* 按钮左侧 8px */
  top: 50%;
  transform: translateY(-50%);
}
```

## 4. 单击逻辑

### 4.1 ↑ 向上

```
1. 获取 currentTurnIndex
2. 判断当前轮的 agentMsg 是否在可视区内：
   agentRect = agentMsg.getBoundingClientRect()
   containerRect = conversation.getBoundingClientRect()
   prevAgentInView = agentRect.top < containerRect.bottom
                  && agentRect.bottom > containerRect.top
3. targetIndex = prevAgentInView ? currentTurnIndex - 1 : currentTurnIndex
4. targetIndex 不能 < 0
5. smoothScrollTo(turns[targetIndex].userMsg.offsetTop - navBarOverlap())
```

**`navBarOverlap()`**：计算 `.nav-bar` 覆盖在 `.conversation` 顶部的高度 + 40px 额外间距，确保用户消息不被导航栏遮挡。

### 4.2 ↓ 向下

```
1. targetIndex = currentTurnIndex + 1
2. 如果 targetIndex < turns.length → scrollToUserMsg(targetIndex)
   否则（已是最后一轮）→ smoothScrollTo(conversation.scrollHeight)
```

## 5. 双击与快速连点逻辑

### 5.1 状态变量

每个按钮独立维护，互不干扰：

```js
{
  lastClickTime: 0,          // performance.now()
  tooltipTimer: null,        // setTimeout id
  dblclickGraduated: false,  // 双击毕业标记
  rapidStreak: 0,            // 连续快速点击计数
}
```

### 5.2 时间窗口

| 间隔 | 判定 | 行为 |
|---|---|---|
| ≤ 300ms | 双击 | 跳顶/底 + 首次弹提示毕业 |
| 300ms ~ 500ms | 快速单击 | 正常翻页 + 计入 rapidStreak |
| > 500ms | 有阅读停顿 | 正常翻页 + rapidStreak 重置 |

### 5.3 点击处理流程

```
onClick(buttonType):
  now = performance.now()
  elapsed = now - state.lastClickTime
  state.lastClickTime = now

  // 连续快速点击追踪
  if elapsed > 500:
    state.rapidStreak = 0    // 有阅读停顿，重置
  state.rapidStreak++

  if elapsed <= 300:
    // ── 双击 ──
    clearTimeout(state.tooltipTimer)
    removeTooltip(btn)
    执行双击跳转(buttonType)
    if !state.dblclickGraduated:
      state.dblclickGraduated = true   // 毕业
      showTooltip(btn, '双击 ↑ 可跳转对话顶部')
    return

  // ── 单击 ──
  doSingle(buttonType)

  // 连续快速点击 ≥3 次且未毕业 → 教学提示
  if state.rapidStreak >= 3 && !state.dblclickGraduated:
    removeTooltip(btn)
    clearTimeout(state.tooltipTimer)
    state.tooltipTimer = setTimeout(100ms, () => {
      if !btn.hasClass('is-hidden'):
        showTooltip(btn, '双击 ↑ 可跳转对话顶部')
    })
```

### 5.4 设计意图

| 场景 | 用户行为 | 信号 | 提示策略 |
|---|---|---|---|
| 首次双击 | ≤300ms 两次点击 | 用户可能是有意识双击 | 提示一次确认"双击=跳顶"，然后毕业 |
| 连续快速点击 | <500ms 连续 ≥3 次 | 用户不知道双击，试图快速回顶 | 每次都提示，建立认知 |
| 定位消息 | 每次点击间 >500ms | 用户在阅读，不是想回顶 | 不打扰 |
| 毕业后双击 | ≤300ms | 用户已知双击 | 静默执行 |

**核心原则**：提示的目的是**建立"双击=跳顶"的认知映射**，不是教操作。认知建立后提示即毕业。

### 5.5 双击跳转

```
双击跳转(buttonType):
  if buttonType === 'up':
    smoothScrollTo(0)                           // 对话顶部
  else:
    smoothScrollTo(turns[last].userMsg.offsetTop - navBarOverlap())  // 对话底部
```

## 6. Tooltip

### 6.1 显示

```js
showTooltip(btn, text):
  removeTooltip(btn)             // 去重
  tip = createElement('div.sn-tooltip')
  tip.textContent = text
  btn.appendChild(tip)
  setTimeout(2500ms, () => {     // 2.5s 后淡出
    tip.classList.add('is-leaving')
    setTimeout(200ms, () => tip.remove())
  })
```

### 6.2 动画

- **淡入**：`animation: sn-tooltip-in 0.2s ease forwards`（opacity 0→1）
- **淡出**：添加 `is-leaving` class，`animation: sn-tooltip-out 0.2s ease forwards`（opacity 1→0）

### 6.3 屏蔽条件

- 按钮处于 `is-hidden` 状态时不弹
- 新提示替换旧提示（不会叠加）

## 7. 滚动行为

### 7.1 平滑滚动

```js
smoothScrollTo(y) {
  // 1. 预判目标位置的按钮显隐，提前瞬间切换（skipEntrance）
  // 2. 标记 document.body.dataset.snNavigating = 'true'
  //    → 阻止流式输出的 scrollToBottom 打断用户导航
  // 3. 执行滚动（优先 scrollBehavior: smooth，降级 scrollTop 赋值）
  // 4. 清除标记：scrollend 事件 + 500ms 超时兜底
}
```

### 7.2 导航锁（snNavigating）

用户点击按钮导航时，流式输出不应把页面拉回底部。通过 `document.body.dataset.snNavigating` 标记：

- 设置时机：`smoothScrollTo()` 开始时
- 清除时机：`scrollend` 事件或 500ms 超时
- 消费方：流式输出的 `scrollToBottom()` 检查此标记，为 `true` 时跳过

## 8. 特殊状态处理

| 状态 | 处理 |
|---|---|
| 表格全屏（`#tblOverlay.is-active`） | `#scrollNav` 添加 `is-hidden`（MutationObserver 监听 class 变化） |
| 对话未开始（turns 为空） | 按钮隐藏；有内容后需调用 `rebuildScrollNav()` |
| typewriter 正在输出 | 按钮可点，但导航锁阻止流式输出打断用户滚动 |
| `.nav-bar` 覆盖 | `navBarOverlap()` 计算偏移，确保 userMsg 不被遮挡 |
| 对话流折叠 | turns 索引只取 `:not(.is-hidden)` 元素 |

---

## 10. 性能注意事项

- turns 索引在每次新增轮次后全量重建（最多几十轮，O(n) 可接受）
- scroll 事件用 requestAnimationFrame 节流
- `getBoundingClientRect()` 在单击逻辑中调用（不在 scroll 热路径中）
- Tooltip DOM 轻量构建，不引入第三方弹层库
