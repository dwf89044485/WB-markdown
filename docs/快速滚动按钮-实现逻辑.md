# 快速滚动按钮 — 实现逻辑（开发者视角）

> 本文描述 ↑ ↓ 按钮在具体代码层面的状态判断、滚动计算、边界处理。实现前必读。

---

## 1. 数据结构

### 1.1 对话轮次索引

实现时需要实时维护一个**有序的轮次列表**，每轮包含两个 DOM 引用：

```
turns = [
  { userMsg: HTMLElement, agentMsg: HTMLElement },
  { userMsg: HTMLElement, agentMsg: HTMLElement },
  ...
]
```

**`userMsg` 选择器**：`.user-msg-wrap:not(.is-hidden)`，每个非隐藏的 user-msg-wrap 代表一轮的开始。文档顺序即时间顺序。

**`agentMsg` 选择器**：`.agent-msg:not(.is-hidden)`，紧跟在前一个 user-msg-wrap 之后的 agent-msg 属于同一轮。

**获取方式**：在 needRender 或播放结束时，通过 `document.querySelectorAll('.user-msg-wrap:not(.is-hidden)')` 重建。每次播放新增一轮后应更新索引缓存。

### 1.2 当前轮次判定

给定 `.conversation` 容器的 `scrollTop`，找到当前可视区内或紧靠可视区顶部的用户消息所在轮次：

- 遍历 `turns`，取每个 `.user-msg-wrap` 的 `.offsetTop` 相对于 `.conversation`
- 第一个 `offsetTop >= scrollTop - 容差` 的 user-msg 所在的轮次 = 当前轮

> 容差建议 1px，避免浮点精度导致错判。

## 2. 按钮显隐逻辑

### 2.1 判断条件

显隐基于**滚动容器的位置**（不依赖轮次索引）：

```
scrollTop    = conversation.scrollTop
scrollBottom = scrollTop + conversation.clientHeight
scrollHeight = conversation.scrollHeight

↑ 可见 = scrollTop > 5          （不在最顶部）
↓ 可见 = scrollBottom < scrollHeight - 5  （不在最底部）
```

5px 容差用于避免浮点精度或 1px 滚动残留导致误判。

| ↑ 按钮 | 条件 |
|---|---|
| 显示 | `scrollTop > 5`（不在最顶部） |
| 隐藏 | 在最顶部 |

| ↓ 按钮 | 条件 |
|---|---|
| 显示 | `scrollBottom < scrollHeight - 5`（不在最底部） |
| 隐藏 | 在最底部 |

### 2.2 触发时机

每次以下事件发生时重新计算显隐：

- 滚动事件（`.conversation` 的 `scroll` 事件）
- 播放引擎新增一轮后
- 浏览器 resize（不影响对话结构性滚动，但可能影响 `atBottom` 判定）

**防抖**：scroll 事件触发重新计算时，使用 requestAnimationFrame 节流，不与主渲染帧冲突。

### 2.3 按钮定位状态（居中 vs 分列）

按钮用 `position: absolute` + `left: 50%` 定位，分列位置通过 `transform: translateX()` 的偏移量控制，确保 CSS transition 可平滑过渡。

| 可见按钮数量 | CSS class | 定位方式 |
|---|---|---|
| 1 个（↑ 或 ↓） | 不加 `has-two` | `left: 50%; transform: translateX(-50%)` → 居中 |
| 2 个（↑ + ↓） | 加 `has-two` | ↑: `transform: translateX(calc(-50% - 22px))` — 左偏 22px<br>↓: `transform: translateX(calc(-50% + 22px))` — 右偏 22px |
| 0 个 | 加 `is-hidden` | 整个容器隐藏 |

**切换动画**：`transform` 变化触发 transition，0.3s `cubic-bezier(.32,.72,0,1)` 完成从居中到分列的平滑位移。

切换过程分两步走：

1. **从 1 变 2**：
   - 隐藏的按钮先获得 `is-appearing` → DOM 渲染为 `opacity:0 translateY(6px)`（不可见但占据布局空间，触发 flex reflow）
   - 同一帧内移除 `is-appearing` → CSS transition 驱动淡入上移动画（0.2s）
   - 同时 `.scroll-nav` 获得 `has-two` class → `justify-content` 从 `center` 过渡到 `space-between`（0.25s），居中按钮平滑滑向一侧

2. **从 2 变 1**：
   - 隐藏的按钮添加 `is-hidden`（display:none），另一按钮独占一行
   - `.scroll-nav` 移除 `has-two` → `justify-content` 从 `space-between` 过渡回 `center`（0.25s），唯一按钮平滑滑回中央

3. **从 1 变 0 或 0 变 1**：
   - 直接开关 `is-hidden`，不做动画（避免组件刚出现时播放空动画）

> **实现注意**：`justify-content` 不支持 CSS transition（它不是可插值的属性）。实际实现改为：按钮使用绝对定位或 flex + margin 控制位置，用 `transform: translateX()` 做动画。

**替代方案（推荐，已采用）**：两个按钮都用 `position: absolute` + `left: 50%`，分列位置用 `transform: translateX()` 偏移量控制，这样 CSS transition 可以平滑过渡：

```
.scroll-nav {
  position: relative;
  display: flex;
  justify-content: center;
  height: 36px;
  z-index: 5;           /* 高于 composer 渐变遮罩的 z-index:1 */
}
.scroll-nav-btn {
  position: absolute;
  left: 50%;
  transition: transform 0.3s cubic-bezier(.32,.72,0,1), opacity 0.2s ease;
}
#scrollUp, #scrollDown {
  /* 默认居中 */
  transform: translateX(-50%);
}
/* 两个按钮同时显示时：用 translateX 向两侧偏移 */
.scroll-nav.has-two #scrollUp {
  transform: translateX(calc(-50% - 22px));
}
.scroll-nav.has-two #scrollDown {
  transform: translateX(calc(-50% + 22px));
}
/* 入场动画 */
.scroll-nav-btn.is-appearing {
  opacity: 0;
  transform: translateY(6px) translateX(-50%);
}
.scroll-nav.has-two .scroll-nav-btn.is-appearing {
  opacity: 0;
  transform: translateY(6px) translateX(calc(-50% - 22px));
}
.scroll-nav.has-two #scrollDown.is-appearing {
  transform: translateY(6px) translateX(calc(-50% + 22px));
}
```

## 3. 单击逻辑

### 3.1 ↑ 向上逻辑

**输入**：当前 currentTurnIndex（见 §1.2）

**步骤**：

```
1. 获取 currentTurnIndex 对应的 agentMsg DOM 元素
2. 判断 agentMsg 的任意部分是否在可视区内：
   agentRect = agentMsg.getBoundingClientRect()
   containerRect = conversation.getBoundingClientRect()
   上一轮可视 = agentRect.top < containerRect.bottom && agentRect.bottom > containerRect.top
3. 如果上一轮可视 → targetIndex = currentTurnIndex - 1
   否则（完全不可见）→ targetIndex = currentTurnIndex
4. targetIndex 不能 < 0
5. 滚动到 turns[targetIndex].userMsg 的 offsetTop（相对于 .conversation）
   conversation.scrollTop = turns[targetIndex].userMsg.offsetTop
```

**注意**：需要判断的是**上一轮**的 agentMsg 是否在可视区内，而非本轮。

**边界**：如果用户在对话最底部而 currentTurnIndex 指向的就是最新一轮：
- 如果最新一轮的 agentMsg 在上方（用户看不到它），则 targetIndex = currentTurnIndex（回到本轮用户消息）
- 如果最新一轮的 agentMsg 正在显示，则 targetIndex = currentTurnIndex（同上）

### 3.2 ↓ 向下逻辑

```
1. targetIndex = currentTurnIndex + 1
2. 如果 targetIndex < turns.length → 滚动到 turns[targetIndex].userMsg.offsetTop
   否则（已是最后一轮）→ 直接滚到底：conversation.scrollTop = conversation.scrollHeight
```

## 4. 双击逻辑

### 4.1 状态变量

每个按钮（↑ / ↓）各自维护一套独立状态，互不干扰：

```
interface ButtonClickState {
  lastClickTime: number          // 上次点击松开的时间戳（performance.now()）
  showTooltip: boolean           // 是否需要弹提示
  tooltipTimer: number|null      // 延时弹提示的 timer id
}
```

### 4.2 时间窗口

| 窗口 | 范围 | 解释 |
|---|---|---|
| 双击窗 | 松开上次点击后 ≤ 300ms | 判定为有意双击 |
| 学习窗 | 上次点击后 300ms ~ 700ms | 用户可能想双击但慢了，执行单击 + 弹提示教学 |
| 独立操作 | > 700ms | 重置状态，视为独立单击 |

### 4.3 点击处理流程

```
onClick(buttonType):
  now = performance.now()
  elapsed = now - state[buttonType].lastClickTime

  if elapsed <= 300:                          // 双击窗
    state[buttonType] = reset                 // 清零
    执行双击跳转(buttonType)                     // 见 §4.4

  else if elapsed > 300 && elapsed <= 700:    // 学习窗
    执行一次单击(buttonType)                     // 正常翻页
    state[buttonType].showTooltip = true      // 标记需要弹提示
    state[buttonType].lastClickTime = now     // 更新计时起点

  else:                                       // > 700ms，独立操作
    执行一次单击(buttonType)                     // 正常翻页
    state[buttonType].lastClickTime = now

  // 学习窗的提示在 setTimeout 700ms 到期时检测并弹出：
  if state[buttonType].showTooltip:
    在 700ms 到期时弹出提示（见 §4.5）
    state[buttonType].showTooltip = false
```

> **关键细节**：第 2 种情况（学习窗）在 700ms 到期后才弹提示，而不是点击时立即弹出。点击时先执行翻页，700ms 到时如果状态标记为 true 才弹。这样如果用户在 700ms 内又点了一次（触发下次点击循环），不会错误叠加提示。

### 4.4 双击跳转

```
双击跳转(buttonType):
  if buttonType === 'up':
    targetIndex = 0 (最早一轮)
  else:
    targetIndex = turns.length - 1 (最晚一轮)

  conversation.scrollTop = turns[targetIndex].userMsg.offsetTop
```

**无操作条件**：
- ↑ 双击时如果 currentTurnIndex 已经指向最早一轮（button 隐藏状态）→ 不执行
- ↓ 双击时如果 currentTurnIndex 已经指向最晚一轮（button 隐藏状态）→ 不执行

### 4.5 弹出提示

```
弹出提示(buttonType):
  // 去重：如果该按钮的提示已在 DOM 中 → 不操作
  // 位置：button 元素上方居中
  // 内容：
  //   ↑: "双击 ↑ 可跳转对话顶部"
  //   ↓: "双击 ↓ 可跳转对话底部"
  // 展示：淡入 200ms + 保持 2500ms + 淡出 200ms
  // 移除：动画完成后从 DOM 移除
```

**屏蔽条件**（任何一条满足则不弹出）：
- 按钮处于隐藏状态
- 按钮对应的方向已到边界（↑ 在顶部 / ↓ 在底部）
- 同一个按钮的提示正在显示

### 4.6 跨按钮不干扰

- ↑ 和 ↓ 各自维护 `ButtonClickState`，计时互不影响
- 点 ↑ 后 200ms 点 ↓ → ↑ 视为一次独立单击（等待 > 700ms 后重置），↓ 视为一次独立单击（与 ↑ 无关）

## 5. 滚动行为

### 5.1 目标计算

锚定目标为目标 `.user-msg-wrap` 相对于 `.conversation` 滚动容器的 `offsetTop`：

```
conversation.scrollTop = targetUserMsg.offsetTop
```

### 5.2 动画

全部采用**平滑滚动**：

```
function smoothScrollTo(y) {
  if ('scrollBehavior' in document.documentElement.style) {
    conversation.scrollTo({ top: y, behavior: 'smooth' });
  } else {
    conversation.scrollTop = y;  // 降级
  }
}
```

降级用 `scrollTop = y` 对于不支持 `scrollBehavior` 的浏览器（旧版 Safari）。

### 5.3 滚动对显隐的影响

滚动后立即重新计算两个按钮的显隐状态（见 §2.2）。

## 6. DOM 与事件绑定

### 6.1 按钮渲染

按钮在 `index.html` 中的 `.composer` 上方新增：

```html
<div class="scroll-nav" id="scrollNav">
  <button class="scroll-nav-btn" id="scrollUp" aria-label="上一条用户消息">
    <!-- ↑ SVG -->
  </button>
  <button class="scroll-nav-btn" id="scrollDown" aria-label="下一条用户消息">
    <!-- ↓ SVG -->
  </button>
</div>
```

样式在 `styles/base.css` 中新增 `.scroll-nav` 相关 class。

### 6.2 事件绑定

- `click` 事件：绑定在 `#scrollUp` 和 `#scrollDown` 上
- `scroll` 事件：在 `.conversation` 上监听，用于显隐更新
- 初始化：在 `engine/player.js` 或 `engine/core.js` 中合适的初始化时机挂载

> 不推荐使用全局 `document.addEventListener`，应直接绑定到按钮元素。

## 7. 特殊状态处理

| 状态 | 处理 |
|---|---|
| 表格全屏（`#tblOverlay.is-active`） | `#scrollNav` 添加 `is-hidden`（通过 CSS 或在全屏打开/关闭的回调中切换） |
| 对话未开始（所有 user-msg-wrap 都是 is-hidden） | `turns` 为空 → 按钮隐藏；有内容后需重建 turns 索引 |
| typewriter 正在输出 | 按钮可点（不是 disabled 状态），但滚动到目标后可能因 typewriter 追加内容导致位置偏移。**可接受**：下次用户点击时会重新计算 |
| `.conversation` 内有 `.nav-bar` 固定定位的元素 | 导航栏是固定定位 height: 44px，不影响 userMsg.offsetTop 的正确性（offsetTop 相对滚动容器，nav-bar 是 absolute/fixed 定位） |
| 对话流折叠（旧实现的老逻辑中有节点塌缩） | turns 索引只取 `is-hidden` 为 false 的元素，塌缩后的元素不参与索引 |

---

## 8. 性能注意事项

- turns 索引在每次新增轮次后重建（Q: 需要 rebuild 还是 push append？最多几十轮，全量重建即可）
- getBoundingClientRect() 会触发强制回流——在 scroll 事件中不要在同一个帧里反复调用，建议把本次需要的 rect 一次性取完
- 弹出提示的 DOM 可以用 `innerHTML` 构建，不引入第三方弹层库
